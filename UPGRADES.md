# Upgrades

## 0.6.0 — generated from Ethos by ethos-zero 28.0.0; Redeemed answers Redeem

Every type is generated by ethos-zero 28.0.0 (`970459d`), a build dependency: `ethos/library.ethos`, the Energy vocabulary (moved here from energy-nexus's `ethos/library.ethos`, its Flow import now `signal_flow:[ Address ]`), into `src/generated/library.rs`, and `ethos/signal.ethos` into `src/generated/signal.rs`. `build.rs` regenerates both at every build and refuses a committed file that differs. The `wire!` declarations are gone. The contract's identity is still the digest of `ethos/signal.ethos`.

The outputs are reordered: `Read`, `Subscribed`, `Redeemed`, `Changed`, `Refused`. A Signal pairs the n-th output with the n-th input, so `Redeemed` now answers `Redeem`, and the generated `Answering::redeem` yields the `Reset`; `Changed`, pushed to a subscriber, answers no input. On the wire this swaps two tags and nothing else: `Output::Redeemed` archives with tag 2 and `Output::Changed` with tag 3, where 0.5.0 had 3 and 2. The datom text carries names and is unchanged. A 0.5.0 peer reading a 0.6.0 `Redeemed` reads it as `Changed` and fails validation; both binary peers, the Energy daemon and its translator, ship in one energy-nexus package, which moves to 0.6.0 with this contract.

`Refused` is declared once, in the types section, and named by the output (`Refused`, a bare variant carrying the declared type), so its Rust name is `Refused` again (step one generated it in place as `Refused_Data`). Its bytes are unchanged; energy-nexus's Operation names the same type for its failure.

`tests/hand_and_generated.rs` freezes the 0.5.0 hand declarations and archives a value of every type and every variant through both. For every type but `Output`, the bytes are one, each reads back as the other, and the datom texts are one. Each output is archived through the hand variant and the generated variant of the same name: the bytes are one but for the tag of `Changed` (2 to 3) and of `Redeemed` (3 to 2), each one byte, and the datom texts are one. `tests/wire_fixtures.rs` holds every value against the 0.4.0 bytes and texts, with the two output tags swapped in `tests/fixtures/binary.txt`.

The greeting moves once for all of this. ethos-zero 28 refuses the 0.5.0 text (`Duplicate.Input`: a Signal implies `Input` and `Output`), so `Call.{ Caller Input }` is now a type of the types section and the inputs and outputs stand alone; with the reorder and the named `Refused`, the digest is now `-927593971481128314` (was `-301146476426041394`), and a 0.5.0 peer is refused at its greeting. `tests/fixtures/contract.txt` holds the new identity. No Energy socket greets yet; the daemon reads a `Call` frame without a handshake.

Rust names: `Query` is `Input`, `Response` is `Output`; a field holds the newtype its Ethos names (`Window.used: Used`, `Reading.allowed: Allowed`, `Reading.at: At`, `Reset.expires: Expires`, `Threshold.left: Left`, `Pace.expected/used/per_day`, `Caller.process_id: ProcessId`, `Caller.user_id: UserId`), each archiving as its content. `ProviderTarget` and `WindowTarget` are now this crate's, from the library.

**Pace in useful hours; the schedule's types; a target short of whole** (energy-nexus branch `schedule-pace` carried onto the generated contract, with Fable's rulings). New Library types: `Hours`, `Hour` (0 to 23, the owner's local time), `Weekday`, `Usefulness.Percent`, `Baseline.Percent`, `Span.{ Vector<Weekday> From.Hour To.Hour Usefulness }`, `Override.{ Since.Instant Until.Instant Usefulness }` and `TimeZone.String` (an IANA name). `Pace` loses `per_day` (and the `PerDay` type goes) and gains `hours_left: HoursLeft(Hours)`, `useful_left: UsefulLeft(FiniteDecimal)` and `per_useful_hour: PerUsefulHour(FiniteDecimal)`; `expected` is counted in useful hours. Datom text: `{ Codex Week Even 25 35 Over 124 83.5 0.78 }`. `Target.SpendBy` carries an instant and a percent, `SpendBy.{ 1762450320 80 }`: that much of the window spent by that instant (tentative).

`FiniteDecimal` (`src/decimal.rs`) is hand-written and imported by the Library (`:crate:decimal:[ FiniteDecimal ]`): Ethos's intrinsic `Decimal` generates `datom_codec::Decimal`, which would put datom-codec and its text parser into the Energy daemon, whose dependency boundary refuses them. It archives as one little-endian `f64`, refuses a non-finite value on the way in and on reading an archive, and under `datom` its text is datom-codec's decimal (`32.0`, `0.78`).

The `Read` line's comment says pace is in useful hours, so the digest moves again within the unreleased 0.6.0: `-8897529803879169300`. `tests/fixtures/` holds the lines of `Target.Even` (its archive grew to the size of `SpendBy`), `Target.SpendBy`, `Pace`, `Read_Data` and `Response.Read` as 0.6.0 writes them and a line for each new type; every other line is the 0.4.0 line. `tests/hand_and_generated.rs` no longer proves `Target` and `Pace` against 0.5.0, since they change by design.

## 0.5.0 — signal 11.0.0 and signal-flow 61.0.0

Branch-only preparation for the Flow 0.54.7 rollout; deployed with it, in the same Home generation, with meta-signal-energy-nexus 0.5.0 and energy-nexus 0.3.2.

Repins signal 10.3.0 to 11.0.0 (`6d4eb74`), signal-flow 57.0.0 (`3d0a4cd`) to 61.0.0 (`4871bb8`, the contract Flow 0.54.7 is built with), datom-codec to `09a0526` and protos to `c93b598` (the pair signal-flow 61 builds with). `signal` declares `links = "signal"`, so a consumer carries one signal: this contract moves with signal-flow 61, which depends on signal 11.0.0.

The Rust types change and the wire does not. `Recipient` wraps signal-flow's `Address`, whose `topic` is now the `Topic` newtype (`Topic("energyNexus".into())`); the binary and datom text of a Recipient and of every other type are unchanged, and the authored `signal.ethos` is unchanged, so the contract digest of this crate's own types does not move. No Ethos output is generated from `signal.ethos` in this repository (it is included as text and checked by a test); nothing to regenerate.

`tests/wire_fixtures.rs` holds the wire against `tests/fixtures/`, made by 97741d2 (0.4.0): the rkyv bytes and the datom text of a value of every wire type and every variant, the contract digest, and the greeting and receipt that carry it. They are identical under 0.5.0.

## 0.4.0 — signal-flow 57.0.0 with Observe.TurnEnds; Read answers the latest reading

Repins signal-flow 57.0.0 at `3d0a4cd` (Observe.TurnEnds, the turn ends the Energy Nexus reads a provider on, and Observe.Metaflows; branch idle-0533-ff3882, not yet a main). The wire types are unchanged. `Read.Provider` now answers the provider's latest reading, read from the provider first when that reading is older than the last turn end on it (or there is none); before, every `Read` read the provider. The authored `signal.ethos` says so on the `Read` line, so the contract digest changes.

## 0.3.0 — signal 10.3.0, datom-codec 0.33.0, protos 0.33.0, signal-flow 57.0.0

Repins signal 10.3.0 (`7afb`), datom-codec 0.33.0 (`eabe`), protos 0.33.0 (`3c7a`), the dev generator ethos-zero 19.2.0 (`5a5d`) and signal-flow 57.0.0 (`065730f`, the contract Flow 0.53.3 is built with; branch idle-0533-ff3882, not yet a main).

- `Recipient` wraps signal-flow's `Address`, which since 51.0 names a model (in 57.0.0 it is flow-ethos's `Address.{ Aspect Topic Model }`, re-exported): `Address { aspect, topic, model }` replaces `Address { aspect, topic, layer }`, and `Layer` is gone. The Recipient wire form, binary and datom text, changes with it: `Mind energyNexus Secondary` becomes `Mind energyNexus Sol` or another `Model`. A consumer that builds a Recipient replaces `layer: Layer::…` with `model: Model::…`. The authored `signal.ethos` and the other wire types are unchanged.
- The unit tests add a binary and a datom-text round trip of a `Reminder` whose recipient names a model.
- Known and inherited: signal-flow 57.0.0 and its flow-ethos list ethos-zero 17.0.0 (`07714b0`) as a build dependency, which carries protos 0.32.2 and datom-codec 0.32.2 into a consumer's lock beside the 0.33.0 pair this crate selects; the lock holds both until signal-flow repins that generator.
